## Introducción
> **Nota**: este documento continúa directamente el proyecto iniciado en el apunte anterior, y asume que ya estás familiarizado con JSX y *props*, así como con los componentes `App` y `BookItem` usados en los ejemplos.

Hasta este momento, nuestro mini-proyecto creado no es muy interesante para el usuario, ya que solo nos provee valores estáticos que no podemos interactuar o cambiar. Por ejemplo, no podemos agregar nuevos libros que leímos ni borrar los que ya vienen de nuestro código. En las siguientes secciones veremos cómo manejar eventos e interacciones con el usuario para darle dinamismo a nuestra aplicación.

## Manejo de eventos
Vamos a agregar un botón que cambie la disponibilidad del libro que deseemos. Agregamos un nuevo botón  al jsx del componente "BookItem", abajo del contador de páginas. 

A todos los elementos de jsx que hacen de elementos de HTML se le pueden pasar como props los manejadores de eventos que su contraparte de HTML posee (pensemos en eventos como onClick, onFocus). Entonces, podemos agregar al elemento button un atributo onClick.

Pero, ¿Cómo lo escribimos? A onClick le vamos a pasar una función entre las llaves, ya que son atributos que esperan ejecutar código ante interacción del usuario. Escribiremos entonces:

```jsx
<button onClick={() => console.log("Clicked")}>
	Cambiar disponibilidad
</button>
```
Ese código nos muestra que cada vez que hacemos click en el botón, en consola imprimirá "Clicked!!". Lo comprobamos apretando F12 en el navegador.

Recordemos que es ideal que no tengamos demasiado código en nuestro jsx, por eso moveremos está lógica a una variable más arriba y luego haremos referencia directamente a la misma en el botón:

```jsx
const handleChangeAvailability = () => {
	console.log("Clicked");
}
```
```jsx
<button onClick={handleChangeAvailability}>
	Cambiar disponibilidad
</button>
```
Un par de cosas a remarcar:
* Dentro del jsx, donde hacemos referencia a la función handleChangeAvailability no ponemos paréntesis. ¿Por qué no? Porque si los pusiéramos, la función se ejecutaría inmediatamente al renderizar el componente, en lugar de esperar a que el usuario haga click. De esta manera, solo hacemos la referencia, y se ejecuta solo cuando el usuario hace click.
* Es buena práctica siempre que se manejan eventos de poner handlexxxx como nombre de función, donde xxxx representa lo que nosotros queramos, pero siempre lo comenzamos en handle para dar a entender que esta función está relacionada a eventos y no a otra cosa. Esto es, de todas formas, opcional.

## Estado (*state*) en React
Reflexionemos un poco sobre lo que queremos hacer:
1. Deseamos cambiar el título de los libros, cambiando el contrario de lo que nos haya venido por *props* en isAvailable.
2. Para ello, debemos tomar lo que está en isAvailable y reemplazarlo por su contrario.
3. Luego React debe re-renderizar el componente y mostrar la nueva etiqueta en el `BookItem` correspondiente.

¡Parece un montón! Pero React nos proporciona, dentro de su librería, una función, del tipo hook o "gancho", llamada *useState*. Todos los hooks de React (y hay varios, además de que podemos crear los nuestros) comienzan con la palabra *use*. useState solo puede ser llamada dentro del componente, no puede ser llamada fuera del mismo o dentro de una función anidada (como handleChangeAvailability).

```jsx
import { useState } from 'react';
```

Entonces, dentro del componente llamaremos a *useState*(). *useState* recibe como parámetro el **valor inicial que queremos darle a una variable** que creará React. En este caso, le pasamos *isAvailable*.

¿Qué retorna *useState*? Retorna un arreglo con dos valores, el primer valor es nuestra nueva variable ya inicializada y el segundo es una función que nos servirá para setear el valor de dicha variable. Podemos utilizar *array destructuring* para obtener ambos, ya que en *array destructuring* solo importa la posición de los elementos.

```jsx 
const [available, setAvailable] = useState(isAvailable);
```

Es común que el primer elemento tenga un nombre representativo de lo que es, y el segundo sea la palabra set seguida del nombre del primer elemento.

Entonces, dentro de nuestro handleAvailableClick llamaremos a setAvailable y le pasaremos como parámetro el nuevo valor que deseamos actualizar, además de imprimirlo en consola en la misma función:

```jsx
const handleChangeAvailability = () => {
	setAvailable(!available);
}
```

```jsx
<span 
className={`book-card__badge 
	${available
		? 'book-card__badge--available' 
		: 'book-card__badge--reserved'}`}>
	{available ? 'Disponible' : 'Reservado'}
</span>
```

Entonces, para poder cambiar la interfaz de usuario ante acciones de él o ella, se recomienda crear e implementar un *state*.

### Actualización correcta del estado en base a un estado anterior
Una pequeña aclaración que debemos agregar es que, en el caso de que vayamos a actualizar un estado en base a un estado anterior, se recomienda y es buena práctica hacerlo mediante una *callback* que recibe el estado anterior como parámetro,  y en la que devolveremos el nuevo estado a reemplazar.

Entonces como al setear *available* utilizamos información del estado anterior, el set quedaría así:

```jsx
	setAvailable((prevAvailable) => !prevAvailable);
```

Volveremos a ver esta forma de setear estado cuando modifiquemos la lista de libros en la sección siguiente.

## Agregando libros al formulario
Hasta ahora solo modificamos datos que ya existían (la disponibilidad de un libro). El siguiente paso es permitirle al usuario **agregar libros nuevos** a la lista, y para eso necesitamos un formulario.

Creamos entonces un componente `BookForm`, dentro de su propia carpeta `bookForm`, siguiendo la misma organización que venimos usando para el resto de los componentes. Este formulario no se muestra todo el tiempo: solo aparece cuando el usuario hace click en un botón "Agregar libro". Para lograr esto, en el componente `App` creamos un nuevo *state* booleano:

```jsx
const [showForm, setShowForm] = useState(false);

const handleShowForm = () => {
  setShowForm(true)
}

const handleHideForm = () => {
  setShowForm(false)
}
```

Y en el jsx, renderizamos `BookForm` de forma condicional usando el operador `&&`, un patrón muy común en React para mostrar u ocultar elementos según una condición:

```jsx
<main className="book-grid">
  {showForm && <BookForm onClose={handleHideForm} onAdd={handleAddBook} />}
  {/* resto de la lista de libros */}
</main>
```

Cuando `showForm` es `false`, la expresión `showForm && <BookForm />` se resuelve directamente en `false`, y React no renderiza nada. Cuando es `true`, se resuelve en el componente y React lo muestra en pantalla.

**Nota**: siguiendo la convención de separación de archivos por responsabilidad, el valor inicial del formulario (todos los campos vacíos) no se declara dentro de `BookForm.jsx`, sino en un archivo aparte `BookForm.data.js`, ya que se trata de un objeto de datos *hardcoded* y no de lógica del componente:

```jsx
// BookForm.data.js
export const formInitialState = {
    title: "",
    author: "",
    publisher: "",
    rating: "",
    pageCount: "",
    imageUrl: "",
    isAvailable: false,
};
```

## Escuchando el input de los usuarios
Ya tenemos el formulario apareciendo en pantalla, pero todavía no reacciona a lo que el usuario escribe. Para eso, dentro de `BookForm` vamos a crear un *state* que representará **todos los datos del formulario en un único objeto**, en lugar de crear un *state* separado por cada campo (uno para el título, otro para el autor, etc). Esto nos evita repetir la misma lógica siete veces y nos deja un solo lugar de dónde leer y actualizar los datos del formulario:

```jsx
import { useState } from 'react';
import { formInitialState } from './BookForm.data';

const BookForm = ({ onClose, onAdd }) => {
    const [form, setForm] = useState(formInitialState);
    // ...
}
```

Ahora, para que el input muestre y actualice ese *state*, necesitamos dos cosas en simultáneo:
1. Que el valor mostrado en el input sea siempre el que tenemos en el *state* (`value={form.title}`).
2. Que, cada vez que el usuario tipee algo, actualicemos ese *state* con lo nuevo escrito (`onChange`).

A este patrón, donde el valor del input y el *state* de React siempre están sincronizados en ambas direcciones (el *state* define lo que se ve, y lo que el usuario escribe actualiza el *state*), se lo conoce como ***two-way data binding***, y a un input manejado de esta forma se lo llama **input controlado**.

```jsx
<input
    className="book-form__input"
    type="text"
    id="title"
    name="title"
    placeholder="Cien años de soledad"
    value={form.title}
    onChange={(event) => handleInputChange(event, "title")} />
```

`handleInputChange` recibe el evento del input y el nombre del atributo que queremos actualizar (`attr`). Usamos el operador *spread* para copiar el resto del formulario tal cual estaba, y **propiedad computada** (`[attr]`) para sobrescribir únicamente el campo que cambió:

```jsx
const handleInputChange = (event, attr) => {
    setForm((prevForm) => (
        {
            ...prevForm,
            [attr]: event.target.value
        }))
}
```

El resto de los campos de texto y numéricos (`author`, `publisher`, `rating`, `pageCount`, `imageUrl`) siguen exactamente el mismo patrón: `value={form.campo}` junto con `onChange={(event) => handleInputChange(event, "campo")}`.

El checkbox de disponibilidad es un pequeño caso especial: los inputs de tipo `checkbox` no tienen un `value` que reflejar sino un estado marcado/desmarcado, representado por la prop `checked` (en lugar de `value`), y el evento nos da ese valor booleano en `event.target.checked` (en lugar de `event.target.value`):

```jsx
<input
    className="book-form__checkbox"
    type="checkbox"
    id="isAvailable"
    name="isAvailable"
    checked={form.isAvailable}
    onChange={(event) => handleCheckboxChange(event, "isAvailable")}
/>
```

```jsx
const handleCheckboxChange = (event, attr) => {
    setForm((prevForm) => (
        {
            ...prevForm,
            [attr]: event.target.checked
        }))
}
```

## Manejar los datos ingresados por el usuario
Ya tenemos el *state* del formulario actualizándose con cada letra que el usuario escribe. Ahora necesitamos que, al confirmar el formulario, esos datos se conviertan en un libro nuevo. Para esto, en el elemento `form` de jsx, vamos a escuchar el evento `onSubmit`, que se dispara cuando el usuario envía el formulario (por ejemplo, al hacer click en un botón de tipo `submit`, o al apretar Enter):

```jsx
<form className="book-form" onSubmit={handleSubmit}>
```

Por defecto, el navegador espera que un `<form>` HTML envíe sus datos a un servidor y recargue la página. Como en React nosotros ya interceptamos ese envío para manejarlo con JavaScript, debemos evitar ese comportamiento nativo llamando a `event.preventDefault()` como primera línea de nuestro *handler*:

```jsx
const handleSubmit = (event) => {
    event.preventDefault();
    setForm(formInitialState);
    onAdd(form);
    onClose();
};
```

Acá es donde se nota la ventaja de haber elegido un único *state* `form` para todo el formulario: si hubiésemos usado un *state* por cada campo, `handleSubmit` tendría que armar manualmente un objeto juntando `title`, `author`, `publisher`, etc. uno por uno. Como en cambio ya veníamos manteniendo todos los campos juntos dentro de `form`, al momento del *submit* ya tenemos el objeto completo y listo para usar, sin ningún paso extra de armado.

## Limpieza de los inputs
Una vez que el libro fue agregado, es buena práctica limpiar el formulario para que quede listo para una nueva carga. Como los inputs son *controlados* (su `value` viene siempre del *state* `form`), no necesitamos limpiar cada input manualmente ni usar referencias al DOM: **alcanza con resetear el *state*** al valor inicial, y React se encarga de reflejar ese cambio en cada input automáticamente:

```jsx
const handleSubmit = (event) => {
    event.preventDefault();
    setForm(formInitialState);
    onAdd(form);
    onClose();
};
```

Esta es una de las mayores ventajas de los inputs controlados frente a los no controlados: al ser el *state* la única fuente de verdad de lo que se muestra en pantalla, cualquier cambio que hagamos sobre él (incluido volver a su valor inicial) se ve reflejado en la interfaz sin trabajo adicional de nuestra parte.

## Pasar valores al componente padre
Nos queda un problema por resolver: el nuevo libro fue armado dentro del *state* `form`, que vive **dentro de `BookForm`**. Pero la lista de libros (`books`) vive en el *state* de `App`, un componente distinto. ¿Cómo hace un componente hijo para modificar algo que vive en su padre?

La respuesta es que **no se puede hacer directamente**: React sólo permite pasar datos de padre a hijo mediante *props*. Para lograr el camino inverso (que el hijo le "avise" algo al padre), el padre le pasa al hijo, también como *prop*, una función *callback*. El hijo simplemente la ejecuta cuando corresponda, y es el padre quien decide qué hacer con esa información. A este patrón se lo conoce como ***lifting state up*** ("levantar el estado"): el estado que necesitan compartir varios componentes se ubica en el ancestro común más cercano, que en nuestro caso es `App`.

Así, `App` le pasa a `BookForm` dos funciones por props: `onAdd` y `onClose`.

```jsx
{showForm && <BookForm onClose={handleHideForm} onAdd={handleAddBook} />}
```

Dentro de `BookForm`, ya vimos que `handleSubmit` simplemente llama a esas funciones recibidas por props, sin saber ni importarle qué hacen exactamente con esos datos:

```jsx
const handleSubmit = (event) => {
    event.preventDefault();
    setForm(formInitialState);
    onAdd(form);
    onClose();
};
```

Quien sí sabe qué hacer con esos datos es `App`, que define `handleAddBook` y la conecta al *state* `books` que declaramos en la sección anterior. Usamos la forma de actualización basada en el estado anterior (como vimos en [Actualización correcta del estado en base a un estado anterior](#actualización-correcta-del-estado-en-base-a-un-estado-anterior)) para agregar el nuevo libro al principio del arreglo existente, sin perder los libros que ya estaban:

```jsx
const handleAddBook = (book) => {
  setBooks((prevBooks) => {
    const latestId = Math.max(...prevBooks.map((b) => b.id));
    return [{ ...book, id: latestId + 1 }, ...prevBooks];
  });
};
```

De esta manera, cerramos el ciclo completo: el usuario escribe en el formulario (*state* local de `BookForm`), al confirmar se dispara una *callback* recibida por *props* (`onAdd`), y esa *callback* termina actualizando el *state* del componente padre (`books` en `App`), que es quien realmente controla qué libros se muestran en pantalla.
